# 模型可见指导的写法与审查

适用于 Prompt、Skill、Tool 描述、AGENTS、模型可见任务、内置方法和相关规则。目标是使模型在真实任务中稳定采取正确下一动作。

## 恢复真实目的

先确认这段指导要补偿哪种模型能力缺陷、哪些情境会实际触发，以及结果怎样被后续工作使用。Brain 的用户意图本质与事实本质来自真实形成关系，详见项目 Base04；审查与改写相关 Prompt 时要保留以下区别：

- **用户完整意图**：消息可能省略背景或只提出想到的办法。查清现实对用户活动的影响，结合用户处境、关切和约束，追查为什么提出要求、实际想取得什么结果、希望模型承担什么；区分用户的目标、对原因的猜测、手段建议及明确决定。
- **事实本质**：用户看到的现象可能是下游结果。默认沿直接原因、上游规则和结构、关键分支及中间作用关系深入调查，以实际证据处理竞争解释，按已经确认的深挖停止条件结束；不能把抽象概括或第一层合理解释当根因。
- 两种认识互相校验，事实调查可以发生在意图工作中；新事实影响旧意图或处理方法时修订实际受影响部分。阶段划分帮助模型聚焦，不能切断这条形成关系。

## 写明模型真正需要执行的动作

- 对已确定动作，直接写清**何时、对什么、做什么**。条件决定下一动作时，明确条件与对应动作；已有确定分支不要改成空泛的“自行判断”。
- 当顺序影响结果，写清先后。例如主动调查专业实践及其依据、按用户完整目标设定验收标准及验证方式、再形成可修订计划和实际执行。
- 指明模型需从何处取得真实证据、何时继续追查、怎样修订旧认识、什么结果供后续使用。重要要求放在模型第一次真正需要采取该动作的位置。
- 以模型擅长的聚焦任务、真实工具行动和必要的整体复核组织工作；程序已经能稳定保证的身份、状态或顺序留给程序。
- 模型已经理解的普通概念直接使用；减少结果口号、重复表述、无关枚举、审阅者解释、过度防御和假想限制。优先正面方法，必要的明确禁止、边界和历史真实失败保障继续保留。
- Markdown 表达整体层级与稳定顺序，XML 仅在局部边界确有必要时使用。少量示例用于展示不直观的操作或分支，假设示例不得暗中成为事实或新增约束。

## 逐处保护原有语义

改变每个词句前，取得完整旧正文、用户原始要求及相关模型可见组合，核对：

1. 原有目的、默认与例外、触发条件、先后顺序、用户/模型/程序权属是否保留。
2. 原有停止条件、证据门槛、未确认状态、后续修订和交付边界是否保留。
3. 本次改动会改变模型在什么真实条件下的什么动作，是否有对应依据。
4. 提示词、Tool description、宿主入口、引用的其它方法及结果消费者是否一致。

已发生的典型回归：把“无法有依据确认简单时按实际依赖分层”改成“复杂时分层”，会让模型在不能确定复杂的情况下跳过必要方法；把“默认网络调查，若不查需具体理由”改成“认为外部资料可能改变判断时再查”，重新把决定权交给可能过度自信的模型。这些是检查同类条件弱化的样本，不应机械生成其它禁令。

具体修改需遵守主 Skill 的用户审核与真实验收要求。将一个局部纠正归纳为有依据的通用判据，检查完整指导中的相关同类位置，只改实际受影响处。
