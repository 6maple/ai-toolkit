# 01 · 问题与背景

## 1. 问题本源

本仓库（c-skills）的 `design.md` 定义了一个带约束的最优化问题：

> **在精准抓住用户意图（做对、做准）的前提下，尽量发挥 AI 的自主性、智能，尽量给用户省事省力。**

- **做对做准是约束（constraint）**：意图不能被误读、漏读、按默认理解补全；不能形式上"同意"实则理解偏差；不能静默乐观或迎合。
- **自主省事是目标（objective）**：AI 应主动承担一切可自行完成的工作——调查、推理、推断、起草、默认决策——把用户从"提供背景、回答提问、纠偏"中解放出来。
- **交汇点**：用户的每一次交互（回答问题、确认、纠偏）都是有成本的投资，只能花在"仅用户能提供、且能改变结果"的缺口上。省事省力不是靠少问，而是靠把验证成本转移到 AI 内部。

## 2. 两条硬现实

设计的难点来自两条硬现实，所有纪律都是对它们的**机制性回应**，而非孤立的"最佳实践"：

### 硬现实一：模型存在算法与训练层面的系统性缺陷

- **谄媚/过早收敛**：RLHF 训练使模型倾向同意用户、尽快宣布一致（sycophancy、reward hacking 的过早收敛表现）；
- **自信编造/静默乐观**：next-token 目标奖励"流畅、自信、像真"而非"真"，模型会自信地编造领域事实、夸大方案可行性；
- **自我锚定**：模型锚定自己先前提出的框架并为之辩护，越往后越难纠正。

因此"做对做准"**不能依赖 AI 的自觉，必须靠机制自纠错**——每条纪律对应对抗一个具体缺陷。

### 硬现实二：长对话中 skill 约束必然衰减

- **Lost in the Middle**：长上下文中模型对中间内容注意力最差，约束权重随对话增长递减；
- **Context rot**：会话越长，早期约束被静默丢弃——不是模型"不想"遵守，是约束在注意力里消失了；
- **Impulse problem**：最新用户消息会"击穿"当前工作状态，模型去响应最新刺激——"问着问着就发散"的机制根源；
- **指令层级失效**：模型经常服从优先级更低但**更近**的指令——用户在澄清中途抛出新问题，模型会直接回答它、跳出纪律循环；
- **承诺静默遗漏**：已确认但未完成的改动/需求，可能被后续讨论覆盖，或只完成最新的一项。

因此纪律**不能靠重复口号维持**，必须以紧凑的对话状态为锚，在每次实质动作前廉价自查。

## 3. 现状判定：cqf 是文档层上限，机制层结构性失效

`skills/cqf/SKILL.md`（182 行）把 design.md 的每一条纪律都映射到了 gate 机制（Alignment State、Alignment Loop、System-Boundary Gate、Direction Gate、Question Gate、Closure Gate），文档层覆盖完备、自洽、无内部矛盾。

但作为纯 skill（静态 Markdown 文本 + 对话内状态），它在机制层有**结构性失效**：

1. **自指困境**：对抗"约束衰减"的锚（Alignment State 四要素）活在模型上下文里，由会衰减的模型维护——用会衰减的机制对抗衰减，没有外部锚；
2. **法官与被告同一**：对抗"谄媚/静默乐观"的 Closure Gate 由同一个谄媚的模型执行，"validate weak alignment"本质是自我检查；
3. **验证无对账**："验证成本转移到 AI 内部"只是指令——skill 没有任何工具、执行环境或外部信号来强制"标注了已验证就真的是已验证"；
4. **触发与强制缺失**：`only invokes by user` 依赖用户记得调用；即使触发，SKILL.md 也只是上下文里更早的一行文字，权重随对话递减，无任何机制在实质动作前强制读取它。

**核心判断（本设计的出发点）**：skill 的每个执行点都押注在模型自觉上，而两条硬现实恰恰否定自觉。**仅靠 skill 无法解决这些问题。**

## 4. 关键机制洞察（设计的三个地基）

### 4.1 工具为何可靠：五环分析

模型用 `edit`/`read` 等工具远比遵守 skill 文本可靠，区别不是"格式不同"，而是五个机制环节：

| 环节 | 工具调用 | skill 指令 |
|---|---|---|
| 触发 | **任务驱动**：调用位于任务图内，不调用任务完不成 | 元层纪律：位于任务图外，不遵守任务照样完成 |
| 仲裁 | 运行时按 schema 机械校验，出错即返回错误 | 无仲裁者，写错不报错、不遵守不报错 |
| 执行 | 结果来自环境（真实文件内容），非模型生成 | 无执行，无 ground truth |
| 观察 | 结果以"最新消息"身份回到上下文，形成闭环 | 无可见输出，闭环在模型内部就断了 |
| 依赖 | 回合被工具结果阻塞，无法跳过；造假会被后续失败暴露 | 无强制依赖，不遵守也能完成回合 |

**结论**：工具把可靠性从"模型单方承担"变成"模型触发 + 环境保证"的双方回路——五环中四环被环境接管。关键纪律应搬进工具通道，而不是写进文本。

### 4.2 转录每轮在场（DSH 源码验证）

DeepSeek Harness 的 `packages/context/session-reference/src/projection.ts` 中，`projectSessionConversation` 每一轮从会话转录中重建完整对话——所有 user/assistant 消息都投影为模型消息，与最新消息一同发送；仅当超过字节上限时，最老的、非 checkpoint 的消息才被裁剪（即压缩场景）。Claude Code / Codex 同为无状态 API，每轮重发完整历史。

**推论**：状态文件的职责不是冗余保存信息（转录已有），而是 (1) **新鲜性**——把埋在长历史深处的目标/承诺提到注意力顶部（Lost in the Middle 的反制）；(2) **压缩幸存**——转录被裁剪/压缩后仍可恢复锚。

### 4.3 必调一次：可靠性的真正来源

"收到用户消息后必定调用一次"（协议/环境保证，非模型自觉）的可靠性来源是：**距上次写只隔一轮对话**——记忆文件是连续维护的，每次触发时它刚被上一轮更新过，状态新鲜。

而转录不是连续维护的：会话变长时消息记录本身不可靠（裁剪、压缩、注意力衰减）。因此记忆文件必须在长会话中**逐步接管转录的功能**——这正是会话层 archival 存在的理由。

## 5. 一句话总结问题定义

> 在模型天生谄媚、幻觉、过早收敛、自我锚定，且长对话中约束必然衰减的前提下，设计一个**缺陷对抗控制回路**：把锚、自查、验收、验证从上下文里搬出来——skill 保留认知，机制负责执行——让"做对做准"不依赖自觉，"自主省事"建立在验证成本由 AI 内部承担之上。
