# 02 · 设计意图与依据

本设计全程遵循"三层机制交叉验证"的方法：任何设计决策都要同时过三关——**LLM 的算法/训练方式**（它本质上是什么、能可靠做什么、会怎么失效）、**人脑工作机制**（被亿万年进化验证过的参考架构）、**顶尖人士的实践**（被真实使用验证的做法）。三关都通过才成立；查证不到的标注为"无依据，落地取舍"，禁止凭空设计。

## 1. 设计原则（定稿）

### 原则一：机制管结构，模型管语义

- **机制**（程序代码）负责：记忆结构（schema、字段、状态机）、确定性规则（分层、衰减、进阶、范围约束）、信号（超限提示、写入结果反馈）、审计（history、note、依据引用）；
- **模型**负责一切语义判断：记什么、怎么写、重要性取值、纠正强度判定、删除还是调整、写哪一层、core 梳理。
- **依据**：程序式不 100% 准确的判断都交 LLM（用户的落地原则）；大脑没有"禁令区"等特殊结构，语义由大脑统一处理，结构保持统一。

### 原则二：工具纯程序化，模型两段式

- **brain_think 运行时 = 100% 固定程序代码**：检索打分、排序、截断、容量检查、落盘、状态维护（FSRS/衰减/计数）全是确定性逻辑，**不依赖任何独立 LLM**；
- 一切语义判断发生在**主模型侧**：相关性判断、记什么、importance 值、梳理 core、选层——通过模型与工具的参数往返表达；
- **检索 = 机械初筛（关键词/fuse 模糊检索，无 RAG/embedding）+ 主模型传 query 精化**。
- **依据**：可测试（程序行为确定）、可复用（不锁模型）、简单；模型最擅长、最可靠的能力是文件操作（ls/grep/read/edit——"工具五环"分析）。

### 原则三：渐进式披露（读 = ls → grep → read）

- 读记忆按 **L0 目录 → L1 摘要 → L2 全文** 三级渐进，复刻 agent 用 `ls|grep|read` 的实际流程；
- 每一级只给"足够决定是否深入"的信息：L0 返回目录行（不展开正文），模型决定深读哪个；
- 内容本来就少时（如候选 ≤ 上限）全列，不机械分层——**自适应用量**；
- 摘要放 markdown frontmatter，与 skills（SKILL.md）的维护方式一致。
- **依据**：agent 文件工具的实际使用流程（用户提出的设计参考）；Anthropic skill 体系的 progressive disclosure；工作记忆容量有限（Cowan 4±1），多则分块、少则一次加载。

### 原则四：落地优先

每个设计决策过三道落地关：① 在存储里怎么表示？② 实现成本多少？③ 用户会怎么遇到它？——不为学术完备性加用户可见的复杂度；**不做预防性设计**（不预测未来场景而提前加机制）；数值类参数"先机制后参数，实测标定"。

### 原则五：记录清晰第一

记忆内容以**表述清晰无歧义为第一优先**，去除冗余，仅在保持精准的前提下保守地简洁化；**宁可触发容量提示，不可为省字符牺牲准确**。依据：交流过程中因表述不准导致的误解比比皆是（实践观察）。

### 原则六：依据标注约定

讨论中所有数值/机制/取舍都明确标注依据等级：**[有依据]**（可查证的科学/实践证据）、**[部分依据]**（模式有据、数值无据）、**[无依据，落地取舍]**（无直接证据，基于推断链或实现权衡）。此约定贯穿本设计文档。

## 2. 人脑机制参考

| 机制 | 内容 | 对应设计决策 | 来源 |
|---|---|---|---|
| 知觉-行动循环 | 行为是环境刺激驱动的循环；思考不是自发连续流，由外部事件触发、服务于行动 | "收到消息才思考，行动完成即停"；必调一次的事件驱动模型 | Fuster, *Prefrontal Cortex and the Bridging of Temporal Gaps in the Perception-Action Cycle* |
| 蔡加尼克效应 | 未完成任务占据工作记忆、持续闯入；完成的任务被释放 | 行动完成即停止思考；未决承诺会在下轮 think 重新加载（机制自洽） | Zeigarnik 效应 meta 分析 (2025) |
| 事件分割 | 人把连续经验分割成事件，**事件边界是记忆编码/更新的关键时刻** | "反思+存记忆延迟到下一触发点"（新消息到达 = 事件边界 = 编码窗口）；"思考完成后、行动前存记忆"（反思产物在工作记忆中保真度最高时编码） | Zacks, *Segmentation in the Perception and Memory of Events* |
| 前瞻记忆 | 意图保持需要线索，负荷下纯保持失败率高 | 写记忆不能靠"记得写"（前瞻记忆负担）；"必调 + 读结果引导"把前瞻记忆变成线索触发 | Einstein & McDaniel |
| 检查单 | 顶尖专家在高压下用检查单外部化工作记忆 | 每次消息自动运行的"检查单"（必调机制） | Gawande, *The Checklist Manifesto* |
| 工作记忆容量 | 容量 ~4±1 chunk，衰减快 | L0 候选 10 条、core 每层 1 篇文档（长度上限）的预算；渐进式披露 | Cowan |
| 技能三阶段 | 认知（需完整指令）→ 关联 → 自主（自动、低负荷） | 技能成熟度维度（confidence/usage），新技能带完整步骤，多用后可精简 | Fitts & Posner |
| 用进废退 | 不用的连接被修剪、用的被强化；修剪针对"长期不用"而非"最近不用" | 多级 LRU + 高频进阶；衰减/驱逐按"距上次使用的调用次数" | 突触修剪综述 |
| 双力理论 | 提取强度（快速衰减，提取后回升）+ 存储强度（几乎不衰减，靠成功使用累积） | 记忆项双维状态：retrievability（LRU 语义）+ stability（进阶语义） | Bjork & Bjork, *New Theory of Disuse* |
| 三状态模型 | 难度 + 稳定性 + 可提取性；间隔按稳定性增长 | **FSRS 作为多级 LRU 具体实现的指导（权重、参数）** | FSRS / open-spaced-repetition |
| 再巩固 | 记忆被检索后进入不稳定窗口，可被更新/强化/削弱 | "用户纠正发生在记忆刚被读取采纳之后"正是改写窗口；纠正路径的设计 | Nader et al.；*An Update on Memory Reconsolidation Updating* |
| 奖赏预测误差 | 逐次试错调节记忆形成：正反馈强化、负反馈弱化 | importance 动态调整（采纳↑、纠正↓、失败归因） | Aberg et al. (Frontiers 2017) |
| 高唤醒记忆抗拒消退 | 杏仁核强化的高重要性记忆更难被削弱 | 高 importance 纠正阻尼（需多次一致纠正才显著降级） | McGaugh, *The amygdala modulates the consolidation of memories of emotionally arousing experiences* |
| 价值引导的记忆维护 | 前额叶持续追踪记忆效用/价值，决定哪些被维持 | importance 不是写入时定死的属性，而是被持续维护的状态 | Nussenbaum et al. (eLife 2021) |

## 4. 用户提出的设计参考（讨论过程中的关键输入）

1. **人说话/做事的流程**：收到外部消息 → 先思考（think_tool）→ 行动 → 停止（不再思考）；下次收到消息时先思考，此时顺带反思前一轮并存记忆；
2. **顶尖人士沟通**：模式匹配（这条消息属于哪套框架）、加载相关框架、维持目标、抑制无关、gist 先行 verbatim 按需；
3. **agent 用 ls/grep/read 的实际流程**：渐进式披露的模型——"如果太多，读前几个，读中间几个去找"；
4. **必调一次的可靠性**："距上次的间隔只差一轮对话"——文件连续维护；
5. **记忆三层、会话中合并**：全局/项目/会话，会话运行时自动合并成一个整体记忆；
6. **用进废退 + 多级 LRU + 高频进阶 + 记忆曲线**，时间单位 = think_tool 调用次数（事件时间，非真实时间）；
7. **模型在约束范围内取值**：用户纠错有不同语气（"这个不太行" vs "禁止xxx!"），importance 调整应由模型在范围内取值，而非固定值；
8. **落地优先**：history 不清理、无 bans 特殊结构、模型自选写层、ask 可配置。
