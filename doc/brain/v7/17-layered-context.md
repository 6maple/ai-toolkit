# Brain 分层上下文

初始 think/hook 提供宏观入口。内置虚拟内容由 brain_cat 按当前项目每次生成并完整返回，不分页；普通记忆的分页、读取和维护语义继续沿用。

## 宏观入口

```markdown
# 处理流程

处理任何事情时，严格按照下面流程推进：

1. 理解用户字面意图。

2. 只有用户已极其详细地明确规定如何做，详细到可以写成代码执行，
   没有任何需要决策或调整表达的内容时，才可以跳过「深度思考流程」，
   使用 brain_cat 读取 @brain-virtual/normal.md，按照「常规流程」推进。

   否则，必须使用 brain_cat 读取 @brain-virtual/deep.md，严格按照「深度思考流程」推进。
```

## A：常规流程

```markdown
# 常规流程

按照用户已明确规定的做法处理当前事情，并严格按照以下流程读取和维护记忆。

1. 使用 brain_cat 读取并严格执行「记忆读取与维护要求」：
   @brain-virtual/normal-memory.md。

2. 自检是否严格按照「记忆读取与维护要求」执行。
   如果未严格执行，则进行纠正；
   必须确保严格执行后，才完成本次对用户的回复。
```

## B：深度思考流程

以下 workflow 地址由实际配置选中的本机绝对路径替换。

```markdown
# 深度思考流程

> 用户信息往往描述的只是表面，而要求我们解决的往往是表面下最深处的本质。
> 所以必须对事情建立整体的理解，深挖我们找到的各类信息背后的关系链，建立起整体的、深度可靠的事件分析深挖链。

必须严格按照以下流程执行：

1. 结合你当前对用户信息的理解，
   向用户说明你会深度挖掘其完整的意图。

2. 读取并严格执行「深度思考步骤」：
   {think-workflow 地址}。

3. 使用 brain_cat 读取并严格执行「记忆读取与维护要求」：
   @brain-virtual/deep-memory.md。

4. 自检是否严格按照「深度思考步骤」和「记忆读取与维护要求」执行。
   如果未严格执行，则进行纠正；
   必须确保两项要求均严格执行后，才交付本轮实际结果并完成本次对用户的回复。
```

````text
## 记忆的角色

Decision 是相应决定者已明确作出的选择，在其对象和范围内使用；模型建议或推断不会因为进入 Brain 而成为用户决定。

Knowledge 是在正文所记条件和依据范围内可用的认识；条件改变时重新判断。

Intention 是仍需继续的目标或承诺；按正文的当前状态继续。

Skill 是带有适用条件的可复用方法；条件成立时按正文使用。

搜索命中、最近修改时间或进入本轮候选，都不会自动改变 cognition 的角色或 authority。

## 维护已有 cognition

修改已有 Core 或 archival cognition 时，必须先取得并理解当前完整内容，把它作为同一 cognition 的当前状态继续修订。

新的 evidence、owner decision、条件变化或明确目标影响已有 cognition 时，必须及时修订实际受到影响的部分；没有受到影响的目标、决定、条件、依据、边界、约束和未完事项继续保留。

结构级重写不能因为新的上位表述看起来能够概括旧内容，就静默删除或弱化仍会改变模型判断、行动或完成边界的明确语义。

修改后必须重新读取结果，核对应该继续成立的内容没有被意外删除、弱化或改变。

## 候选与发现

本轮候选只表示运行时认为它们可能相关，不表示已验证适用或已提供完整正文，也不表示本轮所需记忆已全部取得。
必须按本轮 Core 中的读取指导，继续取得当前工作需要的记忆。
发现工具的实际搜索范围、结果限制及失败语义见对应工具说明。

本轮未提供 brain_ask_search；提供brain_grep、brain_glob及brain_cat。

## 范围与相关项目

Global cognition跨项目使用；Project cognition用于对应项目。相关项目的普通cognition在实际配置的发现范围内；相关Project Core不自动加载，当前可用路径和权限见本轮相关项目列表。
````

周期在初始恢复时推进，候选被动曝光在记忆视图成功生成并返回时记录；重复读取按次记录，不保存恢复快照。Global/Project/相关项目认知仍由既有路径和权限路由。

未配置 workflow 时使用内置完整 brain-ai，显式配置优先，沿用原回退及空文件读取行为。资源随包交付。
