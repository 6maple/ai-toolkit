# brain-ai 适度角色代入草稿

本目录保存供用户审核的完整模型可见正文。以当前 `code/brain-cli/default-memories/skill/brain-ai/` 三份记忆为基线；改写 `core.md` 的专业职责段落及其线下入场示例，改写 `software.md` 的开发者职责段落并加入确认按钮示例。`instructions.md` 原样复制，便于连同完整记忆包审核。此草稿尚未写入默认记忆包或实际 Global Brain。

## 想改变的行为

现有正文已经要求按专业职责工作。增量文字从第一理解开始按当前缺口选职责：意图仍模糊时先调查能区分解释的依据；问题逐渐清楚后承担相应领域的职责，查明需要解决的问题、可取得的依据、方案后果与验收结果。可查的事实先自行取得；角色随任务范围和证据调整，跨领域任务可结合职责。角色只帮助选择方法，不能证明事实；用户独有的目标和重要取舍仍由用户决定。

## 静态情境核对

1. 用户问“为什么这里还要一个确认按钮”：先结合前文和操作流程判断这句话实际在质疑什么；若指向交互必要性，前端职责应推动模型检查操作流程、组件能力和项目约定，再提出有依据的建议。此例已写进 `software.md` 正文。
2. 用户说“手机上筛选太费劲”：沿实际操作检查选项、控件、状态和提交反馈；根据结果决定界面改动及验证范围。
3. 用户说“线下活动入场慢”：先找真实瓶颈，再结合现场流程、界面和服务端的必要职责；多个瓶颈可并存，现场暂不可观察时标明待验证的结果。此例已写进 `core.md` 正文。

以上只能检查草稿文字能否指向合理的下一动作。实际遵循度和改进效果仍需用户用真实任务人工验证。

## 依据

- [Base 初始背景与目的](../../../base/01-origin-and-goal.md)：做对、做准与自主、省事；高水平通用思考是能力目标。
- [Base 长期设计思想](../../../base/02-design-philosophy.md)：具体方法应讲清楚，并考虑较弱模型能否稳定执行。
- [Base 认识论与分析纪律](../../../base/03-epistemic-discipline.md)：角色或模型推断不能代替当前真实依据。
- [v7 通用认知研究](../../02-generalist-cognition-research.md)：角色按当前认知瓶颈选用，作为问题、依据、方法、责任和切换条件的组合。
- [OpenAI 提示词指南](https://developers.openai.com/api/docs/guides/prompt-engineering)：编程任务宜明确角色、职责、工具使用与验证。
- [EMNLP 2024 角色提示实验](https://aclanthology.org/2024.findings-emnlp.888/)：单独加入角色身份没有普遍提高事实问答准确率；该实验不能直接判定本草稿的任务行为效果。
