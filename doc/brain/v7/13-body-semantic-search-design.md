# 13 · 仅按摘要发现记忆的目标与改造（待审核）

本文记录当前讨论的目标：`brain_ask_search` 只根据活跃 archival 记忆 frontmatter 中的 `summary` 做语义发现；正文供 `brain_grep` 按文字查找，并由 `brain_cat` 完整读取。`description` 告诉模型何时值得读取，只作为候选的读取引导。搜索结果呈现路径、`description`、`summary` 和可用的争议标记。这里是设计稿，生产代码尚未切换，模型使用效果由用户人工验证。

## 1. 从当前实现到目标

| 环节 | 当前代码事实 | 目标 |
|---|---|---|
| 索引输入 | `semantic-index.ts` 为 `description` 生成向量。 | 只为 `summary` 生成向量；正文与 `description` 均不进入语义索引。 |
| 更新判定 | `description` 不变时可能复用旧向量。 | `summary` 变化时更新向量；只改 `description` 时更新展示文字；正文变化时保留正常的文档读取与文字搜索，不因正文变化重算语义向量。 |
| 发现结果 | 按记忆返回有限候选。 | 继续按记忆返回路径、`description`、`summary` 和可用的争议标记；排名只供发现，不证明内容适用。 |
| 完整理解 | 模型须另行读取正文。 | 用 `brain_cat` 读取相关候选的完整正文、条件和当前争议；已知正文词句时用 `brain_grep`。 |

现有 `ArchivalDocument` 解析 `description` 与正文，尚未解析 `summary`。现有 `brain_grep` 在 archival Markdown 文件中做文字搜索，实际范围包括 frontmatter 与正文；“正文交给 grep”描述的是发现职责，不额外要求只搜索正文行。该工具的命中片段用于定位，重要结论仍由完整读取支持。

## 2. 摘要怎样写

每次新建或更新 archival 记忆时，模型可见说明都应要求写出并核对 `description` 与 `summary`：

- `description`：当前任务符合什么条件时应读取这份记忆。
- `summary`：正文现在记录的对象、主要认识及会改变适用性的边界；用正文能支持的词语表达，作为语义发现的唯一输入。
- 正文：结论、成立条件、依据、未解之处及必要细节。

例如：

```markdown
---
description: 讨论 Brain 记忆的语义发现范围、文字检索或旧记忆兼容时读取。
summary: Brain 的 ask_search 仅根据记忆摘要发现候选；正文由 grep 按文字查找，候选需要按路径读取，缺少摘要的旧记忆不参加语义发现。
importance: high
---

# Brain 记忆发现

## 依据与边界
...
```

摘要应能让模型按当前事项找到候选，不能只是“记录了相关经验”一类空泛标题，也不能把尚未证实的解释写成结论。它无需复制正文全部细节。正文认识改变时同步修订摘要；适用场景改变时同步修订描述。要求模型在写入和更新时填写这两个字段，是**模型可见文字的要求**；本轮不新增“缺少 `summary` 则拒绝写入或编辑”的校验门槛。现有解析器已要求非空 `description`，那是既有行为。

## 3. 旧记忆与检索边界

缺少 `summary` 的记忆仍可按准确路径读取、按路径发现并由 `brain_grep` 查找，但不会参加仅按摘要的 `brain_ask_search`。不能悄悄退回 `description` 或正文生成向量，否则搜索对象会与目标和工具说明不一致。先完成获批的代码与工具文字改造，再单独进行一轮存量记忆摘要补写：列清实际处理范围，逐份读取正文和当前争议，依据现有结论、条件与未解之处写入并核对 `summary`，不凭标题或旧描述编造。语义搜索在补写完成前只覆盖已有可用摘要的记忆；无命中不等于不存在。这一轮属于认知内容维护，不混入索引重建、CLI 导入或代码迁移。

只在正文细节中出现、摘要没有概括的事项也可能被语义搜索漏掉。这是摘要作为唯一入口的真实代价。若模型已知词句或名称，用 `brain_grep`；如果语义搜索无命中而旧决定可能改变当前行动，根据已有路径、名称或文字线索继续查找。仍无可用线索时，说明具体缺口并继续可完成的工作，不把一次检索当作不存在的证明。

## 4. 最小实现与核对

解析出可用 `summary`，用它取代 `description` 作为唯一向量输入，并按摘要内容判断向量是否需刷新。`brain_ask_search` 的结果同时保留对应的 `summary`、`description` 和争议状态；`brain_ls`、`brain_glob`、`brain_grep` 的展示契约不因此扩展。摘要变化时更新向量和展示，描述或争议变化时更新展示。升级旧索引时，不能把旧 `description` 向量作为摘要向量复用。维持现有按记忆排序与有限结果，不增加正文分段、片段向量或重排层。摘要使每条结果更长，工程核对还需确认输出预算造成的截断会明确告知模型，不能静默少报候选。

工程核对包括：摘要变化会改变语义索引和返回摘要；只改描述会改变候选文字；只改正文不会沿用过时正文读取结果，却无需重算摘要向量；缺摘要的旧记忆可读、可编辑、可 grep 且在补写前不进入 ask_search；删除、移动、争议状态和相关项目边界正确；空集合、排名截止及输出截断准确表述。单独的存量摘要维护完成后再核对其检索覆盖与正文一致性。静态和工程核对不能代替用户对模型实际行为的人工验证。

生产代码与模型可见文字需在完整 Prompt 获得用户明确批准后一起切换，避免工具先承诺尚未实现的能力。较弱模型的主动发现引导见 [08](08-model-facing-and-memory-text-draft.md)，保存方法在可选的 [10](10-default-memory-pack-design.md)；两者的使用审查见 [12](12-weak-model-usage-audit.md)。
