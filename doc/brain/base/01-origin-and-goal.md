# 01 · Brain 的初始背景与目的

## 1. 根目标

Brain 最初不是从“怎样做一个更复杂的记忆系统”出发，而是从一个带约束的用户目标出发：

```text
约束：做对、做准
    准确理解并持续遵循用户真正的目标、取舍、边界和已确认约束。

目标：自主、省事
    AI 主动承担自己能够完成的调查、判断和执行，
    减少用户反复提供背景、回答本可自行查明的问题、重复纠偏。
```

两者必须同时成立。

### 用户意图经过语言表达才成为消息

2026-09-27，用户明确纠正并要求纳入 Base 的根前提：

> 你的理解有个根本上的偏差。在 用户 -> AI -> brain 这条链路上，用户发送的消息往往是不能完整、精确地描述用户的意图的，因为用户有 大脑意图 -> 语言表达 的过程，不能把语言表达完全等同于大脑意图。所以对于用户的消息，应该思考用户为什么发这个消息，而不是把消息理解为用户的大脑意图。

用户的意图经过组织和语言表达后，才成为 AI 能看见的消息；表达未必完整、精确地呈现意图。因此，理解的起点包括用户为什么在当前情境和合作进程中发出这条消息、希望推动什么变化。即使一句话语法完整、表面任务明确，也需要结合其发生背景理解。仅在字面任务确定后补充资料，仍可能沿着错误的问题继续工作。

用户消息、相关前文、既有认识和现实情况共同帮助 AI 形成可修正的意图理解；交流反馈与实际结果继续校正它。用户明确表达的决定在其对象和范围内起作用，AI 对未表达目的的推断仍保持为推断。这一前提要求 AI 主动理解沟通的原因和目标，不预先指定固定提问流程、记忆类型或具体 Prompt。

来源：当前会话 `01a0e0f0-f527-7ce0-824b-668e5c408330` 中上述纠正及随后“对的，这个应该进入base”的确认。具体方法与改动方案在版本设计中继续讨论。

### 日常沟通中的省略

用户明确补充：给 AI 发消息时，用户往往为了省事而简短表达，依赖前文和共同背景，不会把目标、缘由、条件和指代全部写清；有时当前可见的上下文也不足。这与人与人沟通一样，消息字面只是理解意图的一部分。用户期待 AI 主动结合对话、既有决定和可访问的现实资料，推敲真正要解决的问题并补足可查的背景，减少要求用户重新写完整说明的负担。补出的解释仍受证据和用户纠正约束，不能把猜测当成用户已确认的决定。

### 长期合作中逐步理解用户

用户使用 AI 是为了提高效率。连续使用数天、数月后，用户希望 AI 能从其消息、已作的取舍、纠正和合作结果中，逐渐认识这个用户如何提出问题、判断依据、权衡方案和省略表达。面对以后片面的消息，AI 应结合这种长期认识与当前任务，推敲用户可能在意而未明说的目标和条件，主动查证并承担能自行完成的工作，减少用户反复解释和纠偏，提高用户对 AI 合作结果的满意度。

用户直接使用的是 AI；AI 使用 Brain 和记忆来延续、检索和修正对用户及工作的认识。这种长期认识应随新的表达和反馈调整，保留适用范围与依据；从历史互动推测的倾向不能自动成为用户在当前事项上的决定。这里确定的是用户希望获得的能力和使用效果，不预先指定记忆类型、用户画像结构或学习算法。

### 后续明确的长期追求：高水平通用思考

用户随后进一步提出：研究顶尖全能人才在模糊、陌生、跨领域问题中怎样理解问题、追查根因、选择下一步认知行动，并从根本机制逐步推到具体方法；据此探索怎样借助模型、Brain 和 Harness，让模型在真实任务中更稳定地表现出这种高水平通用思考能力。这个追求是 Brain 设计的长期方向，应与“做对、做准／自主、省事”一起保留。它是用户希望达到的能力结果，不预先指定角色扮演、固定检查单、某种记忆结构或控制器为答案。

归档讨论中，用户明确要求这项研究进入 Base，成为后续 Brain 设计的根本依据。具体人类认知研究、向当前模型迁移的解释及候选机制，保留在 [v7 高水平通用认知研究](../v7/02-generalist-cognition-research.md) 和后续版本，按证据修正；它们不自动成为跨版本不变的用户决定。

只追求自主，会得到“很主动地做错事”的 AI；只追求谨慎，会把调查、分析和记忆负担重新交给用户。

因此，**用户交互本身有成本**。AI 主动从对话、项目、工具、外部资料、运行结果或实验取得能够自行取得的依据，并承担专业分析、方案形成和普通实现选择。查阅相关资料并深入分析后，仍不清楚用户所指、实际情境或期望结果时，直接澄清影响下一步的具体缺口；用户尚未明确的重要目标、价值、偏好、风险接受、组织约束或授权，由用户补充或决定。已确认的内容按有效范围继续使用，避免让用户重复说明或代替 AI 完成专业工作。

## 2. Brain 要改善的根问题

现实中的 LLM / Agent 并不会因为某条正确 guidance、历史背景或用户决定“存在过”，就在后续工作中一直可靠使用它。

用户观察到并持续关心的是这一类结果：

```text
正确的信息 / guidance / decision 已经出现
≠
以后真正需要时模型一定会正确恢复并使用
```

这会表现为：

- 长对话、上下文压缩、重启或换会话后，重要背景不再可靠控制后续判断；
- 模型只看当前消息或局部材料，忽略更上游的目标、约束和历史；
- 已经形成的方法或规则存在，但模型没有在正确时机想起它；
- 未完成工作、已有决定和关键认识需要用户重新解释；
- 跨天或跨月合作后，模型仍不了解用户反复表达的判断方式和沟通习惯，面对简短消息继续要求用户从头解释；
- 模型基于第一层合理解释继续展开，直到用户再次纠偏。

Brain 因此要帮助 AI 在长期工作中持续恢复和使用真正需要的 cognition，而不要求用户反复承担 continuity 成本。

用户特别强调：Agent 软件即使有记忆，也不保证模型在每条新消息后重新用上适用的思考方法。长对话中的注意力漂移、上下文压缩和换会话，会使早先出现的指导失去实际作用。因此，Brain 的核心诉求之一是让模型在每轮工作中稳定取得当前适用的思考方式和必要认知；只把内容存起来还不够。这里说的是要达到的使用效果，不指定某种固定的注入或检索实现。

用户也明确区分了稳定方法与工作进度：同一项目可能同时有多个会话和多项工作，不能假定存在一份全项目唯一的“当前任务”。本会话已经拥有的瞬时进度不因每轮召回而需要另存；真正要跨会话或跨上下文继续的工作，才按具体事项保留可恢复的目标、决定和当前状态。Brain 应能供不同 Agent 宿主使用，Codex、DSH 等接入方式不定义 Brain 本身。

这里描述的是要改善的用户结果，不冻结具体的 Core、route、memory role、检索算法、Tool 或 Prompt 形态。

### 后续讨论补充的使用背景（2026-09-24）

用户进一步确认：日常工作中，**实际接收任务并完成任务的是模型**；Brain 是帮助模型维持目标、恢复过去已形成的认识并继续工作的支撑。用户希望模型在当前任务中正确理解目标、选取依据、行动、检查结果，并在发现偏差后修正认识。

用户进一步明确：**模型也是 Brain 的直接使用者**。Brain 只是模型 Harness 的增强部分；Brain 建立上下文、读取、检索、写入或宿主接入出错时，对 Brain 能检测且能通过宿主交付的错误，必须把具体问题和可行的下一步交给模型，让模型依据仍可用的上下文、工具和现实资料继续处理任务。若宿主根本没有运行 Brain 接入，或丢弃了其输出，Brain 无法自行保证送达，应如实说明接入限制。一次 Brain 故障不应阻止模型完成其他仍能完成的工作。确实缺少某项重要依据时，模型说明受影响的判断和已尝试的获取方式，不把未取得的记忆说成已经核对。Brain 自己的操作失败可以如实失败并返回原因；失败范围不扩张为整个用户任务的停止条件。

这种需要会出现在不同的工作中。例如，代码、文档和测试都反映过去的设计，而用户现在只模糊地提出一个新功能；旧事故记录给出了一个曾经成立的原因，而当前故障的原因尚未查明；搜索没有命中一项过去的决定，模型便准备断言它不存在；旧测试通过了，但用户这次想要的结果仍未实现。这些是用于检验设计的**情境**，不声称当前仓库已经发生每一种情境，也不把某一种软件流程规定为所有任务的流程。

这些情境指向持续存在的用户需求：模型要能把当前用户意图与已有材料放在各自的适用条件下理解；对自己可以查明的事实主动调查；让重要的意图理解和方案可以被用户辨认、纠正；用实际结果检验是否完成了用户要的事。用户已经确认的目标、决定和授权应继续起作用，尚未由用户决定的重要取舍则不能由模型的合理猜测代替。

模型对目标形成的暂定理解会影响它接下来寻找什么资料、怎样解释资料、何时认为工作完成；早期理解偏差可能沿这条过程扩大。错误也可能发生在信息取得、动作执行和状态更新等独立环节。历史上出现过工具未暴露的情况；检索缺项、结果截断等情况也需要在具体任务中检查。具体原因、补偿机制及其有效性要在当前版本依据观察和测试判断；[v7 正文复核与失效分析](../v7/research/09-prompt-body-writing-review.md)记录了本阶段的推论和待验证事项。

## 3. Brain 不是普通知识库

Brain 保存和恢复的对象不是“越多知识越好”。

它服务的是：

- 跨时间继续有效的目标、决定、约束和理解；
- 未完成工作需要恢复的当前状态；
- 以后仍会复用的方法和项目 cognition；
- 让模型在正确时机重新取得这些内容的入口与机制。

原始 tool output、逐轮聊天过程、模型临时想到但没有长期价值的推理，不因为“可能以后有用”就自动进入长期 Brain。

## 4. 跨版本不变的验收方向

无论未来 Brain 采用什么实现，都应回到这些结果判断：

- 用户已经明确的目标、决定和约束，后续真正需要时能继续起作用；
- AI 不因为 context、session、注意力或触发失败而频繁要求用户重新说明；
- 长期合作中，AI 能逐步形成并修正对用户目标、判断方式和表达习惯的有据认识，在新的片面表达下更准确地预判意图，减少重复说明和纠偏；
- AI 能主动调查自己有能力取得的事实和专业信息；
- 保存和恢复 cognition 不会把模型旧的猜测、误解或幻觉稳定放大成长期 truth；
- Brain 增加的复杂度、上下文和维护成本，确实换来了更少纠偏和更可靠的自主工作；
- 模型在模糊、陌生和跨领域任务中，能更可靠地理解真正问题、选择取得依据的动作、形成可修正的判断并根据结果调整，而不只是在语言上模仿高水平思考；
- Brain 故障能给模型可执行的说明；模型可继续完成不依赖故障能力的工作，用户不会因辅助系统的问题被迫重新启动整个任务；
- 当前机制不再服务这些结果时，可以被重新设计，而不需要维护历史实现形式。

## 5. 明确非目标

下面这些都可能成为某个版本的实现手段，但不是 Brain 的初始目的：

- 某种固定 Markdown / XML / frontmatter 格式；
- 固定的 Core / archival / role / scope 目录；
- 某个 RAG、embedding、GraphRAG、ranking 或 top-k 算法；
- 某组固定 Tool 名称与参数；
- 某个 Host 的 hook / plugin / renderer 接线；
- 某一种 Universal Root、routing graph 或 workflow；
- 为了保留历史实现而保留实现本身。

当前版本必须能够解释自己的机制怎样服务根目标，而不是反过来用现有机制重新定义根目标。
