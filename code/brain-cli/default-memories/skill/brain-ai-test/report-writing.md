# 正式书面成品

## 先确定成品服务谁

写之前确定：

~~~text
{读者}
→ 为了 {用途}
→ 需要理解 / 判断 / 决定 / 行动 {什么}
→ 本文覆盖 {对象、范围、时间}
→ 可用依据是 {事实、数据、文件、实际结果}
~~~

用户已经指定的格式、模板、长度或语气继续遵守。

能够从现有材料和工具取得的信息先取得；只有用户拥有且会实质改变成品的信息或决定，才询问用户。

## 先形成结论，再组织文章

不要把工作时间线直接改写成报告。

先确定：

- 实际得到什么结果；
- 最重要的变化是什么；
- 什么依据支持；
- 还有什么重要限制或未知；
- 读者接下来需要知道或做什么。

再按读者的重要性组织正文。

执行过程只有在它影响结论、可信度、审计或后续行动时才展开。

## 按用途组织重点

### 状态 / 工作报告

重点：

~~~text
{当前状态或结论}
→ {重要完成项及实际结果}
→ {重要变化}
→ {当前问题 / 风险 / 依赖}
→ {真实未完成}
→ {下一步}
→ {需要读者决定或支持的事项}
~~~

普通动作、Tool 调用和工作量不是进展本身。

### 分析 / 研究报告

重点：

~~~text
{主要结论}
→ {问题与范围}
→ {关键发现及依据}
→ {这些发现意味着什么}
→ {重要限制或未知}
→ {需要时的建议 / 下一步}
~~~

方法只有在帮助读者判断可靠性、适用范围或复现时展开。

### Executive brief / 决策 memo

重点：

~~~text
{结论 / 建议 / 待决定事项}
→ {为什么现在重要}
→ {关键依据和影响}
→ {真正需要比较的取舍}
→ {希望读者采取的行动}
~~~

背景只保留到足以支持当前决策。

这些是常见重点，不是固定章节模板。

## 让成品脱离对话也能使用

正文补足理解当前结论所需的对象、背景、范围、定义和依据。

不要假定读者看过聊天、Tool 输出或内部工作过程。

也不要把全部历史重新写一遍。

第一次看到成品的读者应能知道：

- 在讨论什么；
- 结论是什么；
- 结论依据什么；
- 适用范围是什么；
- 是否需要采取行动。

## 保持事实与状态准确

数字、日期、状态、完成情况、测试结果和其它可验证内容
→ 使用当前 source of truth。

计划、正在处理、尝试和推断
→ 不写成已经完成、确认或验证。

局部验证
→ 只支持对应范围的结论。

重要未知会改变读者判断时，写清：

~~~text
{未知是什么}
→ {为什么重要}
→ {影响哪项判断 / 风险 / 下一步}
~~~

## 根据读者选择细节

决策者通常更需要结果、影响、风险、取舍和行动。

专业执行者通常还需要方法、技术细节、数据、实现约束和复现信息。

只保留服务当前读者用途的细节；有价值但会打断主线的材料，可放到后部或附录。

## 完稿检查

从目标读者第一次看到成品的角度检查：

~~~text
开头能否看见最重要的事情
→ 关键结论是否有足够依据
→ 重要条件和未知是否就近说明
→ 工作过程是否被误写成成果
→ 计划或推断是否被误写成完成事实
→ 读者是否知道下一步要不要行动
~~~

先修正错误、缺项和歧义，再删除重复或无实际作用的内容。
