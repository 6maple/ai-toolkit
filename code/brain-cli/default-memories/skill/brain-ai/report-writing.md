# 报告与汇报写作

正式书面成品要让读者在实际使用中获得准确认识，据此判断或行动。按读者和用途选择内容，按实际依据限定结论，补足脱离对话后需要的背景，沿用可靠记录中的事实与状态。先确定这些内容，再选择结构和表达。

下面这种请求属于本文件范围：

```text
写一份发给老板的本周项目进展报告
把这次调查整理成正式分析报告
把这些材料整理成一页 executive brief
根据项目数据写一份状态报告
```

下面这种请求仍属于普通表达，不因为出现“汇报”“总结”就读取本文件：

```text
简单汇报一下现在做到哪了
总结一下你刚发现的问题
告诉我今天改了什么
```

判断标准是：

> 用户是否需要一份脱离当前对话也可以独立阅读、保存、提交或转发的正式书面成品。

## 写之前先确定报告服务谁、解决什么

开始组织正文前，取得这些已经可以知道的信息，结合它们决定报告怎样服务读者：

- 谁会读，为什么读；
- 读完需要理解、判断、决定或行动什么；
- 报告覆盖什么对象、范围和时间；
- 哪些事实、数据、文件或实际结果可以作为依据；
- 用户是否已经指定格式、长度、模板或语气。

已有信息足够就直接工作，缺少的可查信息先自行取得。剩余缺口属于用户目标、偏好、授权或其他无法自行确定的信息，且不同答案会实质改变报告内容时，再询问用户。

## 先根据事实形成判断，再组织报告

不要直接把执行时间线改写成报告：

```text
先做了 A
→ 又做了 B
→ 然后做了 C
```

先重新判断：

- 真正得到什么结果，最重要的变化是什么；
- 这些结果和变化为什么重要，什么 evidence 支持它们；
- 还有什么重要问题、限制或未知；
- 读者接下来需要知道或做什么。

再按读者的重要性组织正文。

执行过程只有在它本身影响结论、可信度、审计要求或读者后续行动时才展开。

## 根据报告目的选择重点

下面各类报告中的箭头表达常见阅读顺序。按具体用途调整内容与顺序，遵守已指定的格式；不把每一项机械设成必备章节。

### 工作报告或状态报告

主要目的是让读者知道当前工作处于什么状态。

优先覆盖：

```text
当前总体状态或结论
→ 重要完成项及实际结果
→ 与之前相比发生的重要变化
→ 当前真正的问题、风险或依赖
→ 仍未完成的重要事项
→ 下一步
→ 需要读者决定、支持或关注的事项
```

不要把普通日常动作、工具调用和工作量罗列成“进展”。

“完成了多少工作”不如“这些工作使当前状态发生了什么变化”重要。

### 分析报告或研究报告

主要目的是让读者理解一个问题以及当前证据支持什么结论。

优先覆盖：

```text
摘要或主要结论
→ 问题与范围
→ 关键发现及对应 evidence
→ 这些发现意味着什么
→ 会影响结论的重要限制或未知
→ 建议或下一步（确实需要时）
```

方法、调查过程和资料来源只有在帮助读者判断结论可靠性、适用范围或复现结果时才展开。

不要因为文档叫“报告”就机械增加 methodology、recommendations、appendix 等章节。

### Executive brief、决策 memo 或面向决策者的汇报

主要目的是帮助读者快速理解问题并作判断或决定。

优先：

```text
先说结论、建议或需要决定什么
→ 为什么现在重要
→ 最关键的 evidence 和影响
→ 真正需要比较的选项或取舍
→ 希望读者采取什么行动
```

不要从完整研究过程或历史背景开始。

背景只保留到足以支持当前决策。

## 让报告可以脱离当前对话独立理解

补足理解结论所需的对象、背景、范围和定义，让读者无需查看前文聊天或工具输出。普通概念直接使用，重复历史删去；仍会改变理解或行动的内容保留。

设想读者第一次看到这份报告，检查他能否从正文知道：

- 报告在讨论什么；
- 关键结论依据什么；
- 结论适用于什么范围；
- 下一步是否需要自己行动。

缺少这些信息时补充。

## 标题和段落承担明确作用

标题说明该部分讲什么，段落围绕一个主要意思展开，重要结论通常在前，后接事实与解释。并列信息用列表，同维度比较用表格；不机械拆成单句段落或增加多余空行。已有组织模板、公司规范或指定格式时，优先遵守。

## 事实、判断和完成状态必须准确

报告中的数字、状态、日期、完成情况、测试结果和其他可验证内容，以当前真正的 source of truth 为准。

不要把：

```text
计划进行
正在处理
尝试过
模型推测成立
```

写成：

```text
已经完成
已经验证
已经确认
```

结论只扩大到 evidence 真正支持的范围。

例如：

```text
测试覆盖了 A
→ 可以报告 A 已通过相应测试

没有验证 B
→ 不能据此写成整个系统已经验证完成
```

存在会改变读者判断的重要未知时，直接说明：

```text
现在还不知道什么
→ 为什么这个未知重要
→ 它会影响哪项判断、风险或下一步
```

## 根据读者决定细节深度

管理者或决策者通常优先需要：

```text
结果
影响
风险
取舍
需要采取的行动
```

专业执行者可能还需要：

```text
方法
技术细节
数据
实现约束
复现或验证信息
```

不要因为掌握很多技术细节就全部放进正文。

详细材料有价值，但会打断主要阅读时，可以放到后面的详细章节或附录。

## 完稿后按读者重新检查

完成报告后，从目标读者第一次看到这份成品的角度重新阅读。

检查以下内容：

- 开头是否已经让读者知道最重要的事情；
- 关键结论是否有足够依据；
- 每个章节是否服务于报告用途；
- 有没有把工作过程误写成工作成果；
- 有没有把推断或计划写成已完成事实；
- 有没有遗漏会改变判断的重要问题；
- 读者看完是否知道下一步是否需要自己行动。

先修正错误、缺项和歧义，再删重复或无用内容。改写后核对关系、条件指向、完成状态、证据范围和未知是否仍准确。

## 联合示例：把调查结果交给需要作决定的人

以下为教学假设。团队筹备研讨会，已确认远程成员必须实时参加讨论，用户需要一份供负责人选择场地的说明。工作材料中，甲场地报价较低，只有单向直播；乙场地报价略高，具备双向讨论设备，但尚不清楚报价是否包括设备。若只按报价排序，甲场地会显得合适，却没有满足参与方式的已确认要求。

当前结论应写成：“甲场地现有方案不满足远程实时讨论要求；乙场地具备相应设备，费用范围仍需核实。”先自行取得费用范围以及甲场地是否能补足能力的资料，不能把可查的事实直接作为负责人需要决定的问题，也不能因写作而忘记继续调查。

假设随后确认甲场地无法在活动日期提供双向设备。乙场地的费用条件决定接下来怎样处理：

- **所需设备及相关费用范围已查清，实际总费用在已确认预算内：** 更新比较材料并据此建议乙场地。设备包含在场地报价中或另行收费，都按满足活动要求的实际总费用判断。报告开头说明推荐与依据，再给出活动目标、比较范围、报价来源、设备条件和必要后续工作。若选择本身属于用户要求负责人作出的决定，呈交具体建议；不把专业调查交给负责人重新完成。
- **确认实际总价超出预算：** 更新结论和工作材料，继续查可行替代；确实只剩需要改变预算或参与要求的取舍时，再说明影响并请相应决定者处理。
- **所需设备的费用范围或实际总费用仍不清楚：** 保留费用未知，继续取得可查的报价范围；不能将未确认的费用当成已在预算内或已经超支。

报告中的变化来自条件变化。把调查得到的当前判断写进报告，并保持必要工作材料与之相符，不能只把旧结论改成更正式的语气。
